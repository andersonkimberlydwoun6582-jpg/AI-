# Content Standards

## Core requirement

Every page must provide a clear, complete answer or useful function for its assigned intent. Word count is not a quality target by itself.

## Page brief

Before production, define:

```text
URL:
Page type:
Audience:
Primary intent:
Primary keyword cluster:
Main promise:
Required sections:
Required evidence or sources:
Important entities:
Questions to answer:
Internal links in:
Internal links out:
Conversion or next action:
Indexation state:
Review date:
```

## Opening section

The first screen should help users understand:

- what the page or tool does;
- who it is for;
- the answer, action, or next step;
- any important limitation, date, version, or source.

Avoid long introductions that delay the useful content.

## Heading structure

- Use one clear H1 for the page topic.
- Use H2 sections for major sub-intents or steps.
- Use H3 only when a subsection genuinely belongs under an H2.
- Write headings for scanning and comprehension, not keyword repetition.

## Evidence and trust

Use first-party or authoritative sources for factual, technical, medical, legal, financial, product, version, or update-sensitive claims. Record dates and versions where change matters.

Distinguish among:

- verified facts;
- editorial judgment;
- community reports;
- estimates;
- experiments.

## Imported and generated content

Before publication, check for:

- unrelated products, games, brands, locations, or people;
- mistranslations and encoding corruption;
- duplicated titles, descriptions, headings, and paragraphs;
- fabricated facts or unsupported instructions;
- leftover template text;
- mismatched category, slug, and content;
- inaccurate dates, versions, links, and images.

Generated source files should be rebuilt from their source of truth rather than manually patched unless the workflow explicitly says otherwise.

## Images and media

- Use images that support the task or explanation.
- Write alt text that describes the image's purpose and visible content.
- Do not stuff keywords into alt text.
- Preserve source and usage information where required.
- Use suitable dimensions, compression, responsive delivery, and stable aspect ratios.
- Do not use an unrelated promotional image as evidence for a claim.

## Calls to action

A call to action should be the logical next step: use the tool, read a related guide, compare options, check a source, subscribe, contact, or purchase. Avoid repeating aggressive calls after every section.

## Freshness

Pages about changing information need:

- last reviewed or updated date;
- relevant version or time scope;
- source review process;
- a trigger for revalidation.

Do not change dates without materially reviewing the content.

## Multilingual content

- Each locale must be understandable to native readers.
- Do not publish visible mojibake or placeholder translations.
- Locale routes, canonical URLs, hreflang, navigation, and metadata must agree.
- A fallback language should not be indexed as if it were a completed translation.
- Localize meaning and search intent, not only individual words.

## Quality gate

A page is not ready to index when its purpose, source, language, category, canonical target, or internal-link position is uncertain.
